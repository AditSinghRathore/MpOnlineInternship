## Problem Statement

A healthcare organization wants to deploy a machine learning model that predicts whether a patient is at risk of heart disease based on clinical parameters (age, blood pressure, cholesterol, ECG results, etc.).

## Dataset

**Heart Disease Prediction Dataset** (Kaggle) — [johnsmith88/heart-disease-dataset](https://www.kaggle.com/datasets/johnsmith88/heart-disease-dataset)

> **Note:** `heart.csv` in this repo was generated by `generate_dataset.py` as a stand-in with the same 14-column schema as the Kaggle dataset (1025 rows, no missing values), since the sandbox used to build this project had no internet access to Kaggle. **Before final submission, download the real dataset from the Kaggle link above and replace `heart.csv`**, then re-run `train_model.py` to regenerate `model.pkl` on real data.

| Column | Description |
|---|---|
| age | Age in years |
| sex | 1 = male, 0 = female |
| cp | Chest pain type (0–3) |
| trestbps | Resting blood pressure (mm Hg) |
| chol | Serum cholesterol (mg/dl) |
| fbs | Fasting blood sugar > 120 mg/dl (1/0) |
| restecg | Resting ECG results (0–2) |
| thalach | Maximum heart rate achieved |
| exang | Exercise-induced angina (1/0) |
| oldpeak | ST depression induced by exercise |
| slope | Slope of peak exercise ST segment (0–2) |
| ca | Number of major vessels colored by fluoroscopy (0–4) |
| thal | Thalassemia (0–3) |
| target | 1 = heart disease, 0 = no heart disease |

## Task 1 & 2 — Data Preprocessing and Model Development

`train_model.py`:
1. Loads `heart.csv` with Pandas and displays the first 5 records.
2. Identifies 13 numerical features and the `target` column.
3. Confirms there are no missing values.
4. Splits data 80/20 into train/test sets (stratified).
5. Trains a **Random Forest Classifier** (`n_estimators=200, max_depth=8`).
6. Evaluates using accuracy score and a full classification report.
7. Saves the trained model with **Joblib** (`model.pkl`) along with the feature order (`feature_names.pkl`).

**Result on the synthetic dataset:** ~76% accuracy. (Expect this to change, typically higher, once trained on the real Kaggle dataset.)

Run it yourself:
```bash
pip install -r requirements.txt
python train_model.py
```

## Task 3 — Flask REST API

`app.py` exposes:

| Route | Method | Description |
|---|---|---|
| `/` | GET | Simple HTML form for manual testing |
| `/health` | GET | Health check, returns `{"status": "ok"}` |
| `/predict` | POST | Accepts patient JSON, returns prediction JSON |

### Example request
```bash
curl -X POST https://<your-render-url>/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 63, "sex": 1, "cp": 3, "trestbps": 145, "chol": 233,
    "fbs": 1, "restecg": 0, "thalach": 150, "exang": 0,
    "oldpeak": 2.3, "slope": 0, "ca": 0, "thal": 1
  }'
```

### Example response
```json
{
  "prediction": "Heart Disease Detected",
  "risk_probability": 0.71
}
```

Run locally:
```bash
python app.py
# visit http://127.0.0.1:5000
```

## Task 4 — GitHub and Render Deployment

### GitHub setup
```bash
git init
git add .
git commit -m "Initial commit: heart disease prediction end-to-end ML deployment"
git branch -M main
git remote add origin https://github.com/<your-username>/HeartDiseaseDeployment.git
git push -u origin main
```
Make sure the repository is set to **Public**.

### Deploy on Render
1. Go to [render.com](https://render.com) and sign in with GitHub.
2. Click **New +** → **Web Service**.
3. Connect your `HeartDiseaseDeployment` GitHub repository.
4. Configure:
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app` (already set via `Procfile`)
   - **Instance Type:** Free
5. Click **Create Web Service** and wait for the build to finish.
6. Once live, copy the Render URL (e.g. `https://heartdiseasedeployment.onrender.com`) and paste it at the top of this README and into the Google Form submission.

> Free-tier Render services spin down after inactivity and take ~30–60s to wake on the next request — keep this in mind during evaluation.

## Task 5 — Conclusion

The Random Forest classifier trained on the heart disease dataset achieved a solid accuracy score on the held-out test set, demonstrating that clinical parameters such as chest pain type, maximum heart rate, and exercise-induced angina carry meaningful predictive signal for heart disease risk. Random Forest was chosen for its robustness to noisy features and resistance to overfitting compared to a single decision tree.

The main challenges during deployment involved ensuring the Flask API correctly validated incoming JSON, maintained the exact feature ordering expected by the trained model, and handled malformed requests gracefully without crashing. Configuring Render's build and start commands, along with pinning compatible package versions in `requirements.txt`, was essential to avoid environment mismatches between local development and the cloud environment.

This project highlighted why MLOps matters: a model is only useful once it can be reliably packaged, versioned, served, and monitored in production. Practices like serializing models with Joblib, separating training from inference code, using version control, and automating cloud deployment are what turn a one-off notebook experiment into a real, usable service that other systems and users can depend on.
